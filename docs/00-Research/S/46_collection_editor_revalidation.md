# 1. Market Differentiation

## 1.1 🔴 먼저, 개별 축은 전부 이미 존재한다

**"편집 판단"을 구성 요소로 분해하면 각 요소가 이미 상용화돼 있다.**

| 편집의 구성 요소 | 이미 존재하는가 | 근거 |
| --- | --- | --- |
| **언제 보낼지** | 🔴 **표준 기능** | **Send-Time Optimization**이 이메일·마케팅 자동화 플랫폼의 표준 기능이다 [Fact] |
| **보낼지 말지** | 🔴 **표준 기능** | **Suppression Logic** — 억제 리스트, 참여 기반 빈도 상한, 선호 센터 설정이 **발송 시점에 적용**된다 [Fact] |
| **어떤 각도로 말할지** | 🟡 **존재한다** | **"맥락 인사이트가 무엇을 보여줄지뿐 아니라 어떻게 프레이밍할지를 결정한다."** AI가 헤드라인·이미지·레이아웃·CTA 변형을 테스트한다 [Fact] |
| **어떤 조합을 보여줄지** | 🔴 **Stylitics** | Complete the Look, **AOV +39%**, 주요 프로그램의 90%+ 구동 [Fact] |
| **무엇이 부족한지** | 🔴 **무료 앱** | 캡슐 워드로브 갭 탐지 [Fact] |
| **화보를 만드는 것** | 🔴 **Zalando** | 에디토리얼 70% AI 생성, **비용 -90%** [Fact] |

> ## 🔴 **"발행 판단"과 "타이밍 판단"은 차별점이 되지 못한다. 마케팅 자동화의 기본 기능이다.**

**`45` D-2("이번 호를 낼 이유가 있는가")를 차별점으로 제시한 것은 이 조사의 오판이었다.** 정정한다.

## 1.2 🟢 그럼에도 하나가 남는다 — **빼는 판단**

**추천 엔진과 편집자의 전제가 정반대다**(Inference·높음).

| | 추천 엔진 | 편집 |
| --- | --- | --- |
| **전제** | **더 많이 보여줄수록 좋다** | **덜 보여주는 것이 가치다** |
| **"제안할 게 없음" 출력** | 🔴 **없다.** PDP에는 항상 무언가 뜬다 | 🟢 **유효한 출력** |
| **선택압** | 무엇을 **넣을까** | 무엇을 **뺄까** |
| **뺀 것의 운명** | 사라진다 | 🟢 **다음 호로 미뤄진다** |

### 🔑 마지막 행이 가장 중요하다

**Stylitics는 미루지 않는다. 다 보여준다. 그래서 두 번째로 볼 이유를 만들지 않는다.**

**편집은 미룬다. 그리고 미룬 것이 다음 호를 낼 이유가 된다.**

이것이 `18` P-02의 판별 질문 — **"두 번째로 쓸 이유가 서비스 안에 있는가?"** — 에 답하는 유일한 경로다(Inference·중간~높음).

### ⚠️ 그러나 이것도 완전한 공백은 아니다

**드립 캠페인(순차 발송)**이 기성 마케팅 자동화에 존재한다. 차이는 **순서가 고정인가 아닌가**다.

| | 드립 캠페인 | 편집의 미루기 |
| --- | --- | --- |
| 다음 회차 내용 | **사전 고정** | **소유물 변화·반응에 따라 재판단** |

**→ 차별은 성립하나 얇다**(Inference·중간). 심사에서 **"그거 드립 캠페인 아닌가요?"**에 답할 준비가 필요하다.

## 1.3 각 서비스와의 정면 비교

| 서비스 | 무엇을 하는가 | 우리와 갈리는 지점 | 강도 |
| --- | --- | --- | --- |
| **Stylitics** | 조합 제안, 쇼퍼블, 항상 노출 | 🟢 **빼지 않는다 / 미루지 않는다 / 판매 목적이 노출된다** | 🟢 **명확** |
| **Zalando** | 에디토리얼 비주얼 **생산** | 🟢 **생산이지 판단이 아니다.** 우리는 생성하지 않고 선택한다 [`45` D-1] | 🟢 **명확** |
| **Digital Wardrobe** (Whering·Indyx·Acloset) | 고객이 **자기 옷장을 관리** | 🟢 **주체가 다르다.** 옷장 앱은 고객이 열 때 작동(Reactive), 우리는 브랜드가 낸다(Proactive) | 🟢 명확 |
| **AI Styling** (Ask Ralph) | 고객이 **물으면** 답한다 | 🟢 **Reactive vs Proactive** | 🟢 명확 |
| **Luxury CRM** (Burberry Insight Hub) | 데이터 통합 → 개인화 추천, **RFID가 콘텐츠 트리거** | 🔴 **가장 가깝다.** 남는 차이는 **브랜드가 데이터를 갖지 않는다**는 것뿐 | 🟡 **약함** |

**🔴 Burberry와의 거리가 여전히 가장 큰 위협이다.** "제품이 콘텐츠를 트리거한다"는 구조가 동일하다.

## 1.4 "추천 vs 편집"이 실제 차별점이 되는가 — 최종 판정

> ## 🟡 **된다. 단 조건이 셋 다 지켜질 때만.**

| # | 조건 | 어기면 |
| --- | --- | --- |
| **1** | **아무것도 제안하지 않는 호가 실제로 존재한다** | 항상 뭔가 뜨면 = 추천 |
| **2** | **뺀 것이 다음 호로 미뤄지고, 그 순서가 고정되지 않는다** | 고정이면 = 드립 캠페인 |
| **3** | **판매 링크가 편집 판단을 지배하지 않는다** | 쇼퍼블이 목적이면 = Stylitics |

**세 조건 중 하나라도 어기면 이름만 바꾼 추천이다**(Inference·높음).

# 2. AI Necessity Kill Test 재적용

> **`34` 기준:** *"AI를 제거하고 직원 + 콘텐츠 + Rule-based로 바꿔도 핵심 Customer Value의 80% 이상이 남는가? YES면 탈락."*

## 2.1 수정된 판단문 검증

사용자 제시: **"AI가 어떤 고객에게 어떤 MCM 경험을 언제 제공할지 판단한다"**

| 축 | Non-AI 대체 | 잔존 | 판정 |
| --- | --- | --- | --- |
| **어떤 고객에게** | 세그먼트 5~10개 | ~85% | 🔴 탈락 |
| **언제** | Send-Time Optimization (표준 기능) | ~90% | 🔴 **탈락** |
| **어떤 경험을** | 콘텐츠 라이브러리 × 세그먼트 매핑 | ~70% | 🟡 경계 |
| **🟢 무엇을 빼고 무엇을 미룰지** | 드립 순서 사전 설계 | **~55~65%** | 🟡 **조건부 생존** |

**→ 수정된 판단문 그대로는 Kill Test를 통과하지 못한다.** 통과하는 것은 **네 번째 축 하나**다.

## 2.2 🔴 가장 심각한 구조적 문제 — Collection이 존재하지 않는다

> ## **"Collection Editor"인데, 대부분의 고객에게 Collection이 없다.**

| 근거 | 내용 | 등급 |
| --- | --- | --- |
| **럭셔리 반복 구매율 9.9%** | **10명 중 9명이 상당한 구매 후 다시 오지 않는다** | **Fact** [`28`] |
| **Gen Z 67%** | 면세에서 **한 번도 사 본 적 없는 제품**을 구매 | **Fact** |

**AI 필연성이 소유 제품 수에 정비례하는데(Inference·높음), 소유 제품 수는 럭셔리에서 구조적으로 작다.**

```
소유 1개  → "컬렉션"이 아니라 제품 하나 → AI가 하는 일 = 추천        🔴
소유 2개  → 조합 1개                    → 판단 여지 최소             🟡
소유 3개+ → 조합 폭발                    → 편집 판단 성립             🟢
```

### 🟢 완화 요인 — 그러나 부분적이다

| 근거 | 내용 | 등급 |
| --- | --- | --- |
| **방문당 카테고리** | 여행객은 방문당 평균 **1.6개 카테고리**를 구매하며 **Gen Z 1.8 · 밀레니얼 1.7로 평균 상회** | **Fact** |
| MCM 가격대 | 접근 가능한 럭셔리(accessible luxury)로 재구매 주기가 최상위 럭셔리보다 짧을 수 있다 | **Hypothesis** |
| Charm·액세서리 | 저가 진입 품목이 존재해 소유 개수를 빠르게 늘릴 수 있다 | **Hypothesis** |

**→ 첫 구매에서 이미 2개 이상일 가능성이 있다.** 다만 **MCM 자체 데이터가 없어 검증 불가**다.

**🔒 이것이 이 아이디어의 단일 최대 구조 위험이다. 심사에서 "고객이 MCM 제품을 몇 개나 갖고 있나요?"에 답할 근거가 없다.**

| | 판정 |
| --- | --- |
| **`45` 대비** | 🟢 **소폭 개선.** "매거진 생성"에서 "빼고 미루는 판단"으로 좁혀졌다 |

# 3. MCM Brand Fit

## 3.1 🟢 강한 연결 — Client Advisor 확장은 MCM 인과 사슬의 정확한 실행

**MCM이 스스로 제시한 사슬** [QA-4-3, **A급 공식**]:

> **"너무나 많은 시장, 매년 수많은 고객을 상대하다 보니 럭셔리 브랜드에서 신경을 많이 써야 할 맞춤형 케어가 많이 부족합니다. 따라서, AI를 고객이 원하는 것을 한발 앞서 제시하고, 또 지속적인 초개인화 고객관리에 관심이 많습니다."**

| MCM 요구 | 이 아이디어 | 판정 |
| --- | --- | --- |
| **Customer Engagement** ("고객과 더 가까이") | 구매 후 관계를 다룬다 | 🟢 **직결** |
| **맞춤형 케어 부족** (규모 문제) | **어드바이저가 소수에게만 하던 것을 다수로 확장** | 🟢 **정확한 대응** |
| **한발 앞서 제시** | 발행형(Proactive) | 🟢 **직결** |
| **지속적 초개인화 고객관리** | 호가 이어진다 | 🟢 **직결** |
| **재방문 고객 LTV** [QA-4-1] | 두 번째 구매를 겨냥 | 🟢 **직결** |

### 🟢 외부 근거도 이 문제를 지지한다

| 근거 | 내용 | 등급 |
| --- | --- | --- |
| **클라이언트가 `구매 후 어드바이저의 비인격적·부조화한 후속 연락`을 핵심 불만으로 지목** | | **Fact** |
| **VIC 중 20% 미만만 일관되게 인정받는다고 느낀다** | **VIC조차 커버되지 않는다** | **Fact** |
| 두 번째 구매가 가장 어렵고, 이후 세 번째 확률이 급증 | | **Fact** |
| 리텐션 5% 향상 → 이익 25~95% | Bain | **Fact** |

**→ 문제 정의는 이 프로젝트에서 확보한 것 중 가장 튼튼한 축에 속한다**(Inference·높음).

## 3.2 🔴 약한 연결

**⚠️ 이것은 제안이지 검증된 것이 아니다(Hypothesis).** 그리고 억지스럽게 들릴 위험이 있다.

## 4.2 🔴 그러나 하나가 논리를 무너뜨린다

> ### **"유사한 컬렉션을 가진 고객들의 구매 패턴"을 더미로 구현하면 서비스 논리가 붕괴한다.**

| 왜 | 내용 |
| --- | --- |
| **협업 필터링은 실제 데이터 없이 아무것도 학습하지 않는다** | 더미로 만들면 **우리가 답을 미리 정해 놓고 AI가 발견한 척하는 것**이 된다 |
| **심사 반박** | **"그거 하드코딩 아닌가요?"** — 답할 수 없다 |
| **공식 FAQ 충돌** | **"임의 데이터 활용 ... 감점 사유가 될 수 있다"** [OFF-004, Fact]와 **"더미 데이터로 구현해도 무방"** [QA-2-3, Fact]의 정합적 해석은 **"더미 자체는 문제가 아니고, AI가 흐름과 연결되지 않은 것이 문제"**다 [`20` §1.2]. **유사 고객 패턴은 정확히 그 함정이다** — AI 판단이 더미 데이터의 형태에 완전히 종속된다 |

### 🔒 처방

> **입력에서 "유사 고객 패턴"을 뺀다.** 그것 없이도 성립하는 판단으로 설계한다.

**빼도 되는 이유(Inference·중간~높음):** 편집자는 **다른 독자가 뭘 읽었는지로 편집하지 않는다.** 그건 추천 엔진의 논리다. **유사 고객 패턴을 넣는 순간 협업 필터링 = Generic Recommendation(X-01)으로 회귀한다.**

**→ 이 항목을 빼는 것은 손실이 아니라 정합성 회복이다.**

# 5. AI Editor Logic 설계

> **사용자가 가장 중요하다고 지목한 항목.** 편집자가 실제로 내리는 판단을 분해하고 각각에 Kill Test를 적용한다.

## 5.1 편집 판단 5개 분해

| # | 판단 | Non-AI 대체 | 잔존 | 판정 |
| --- | --- | --- | --- | --- |
| **J-1** | **발행 여부** — 이번에 낼 것이 있는가 | Suppression Logic (표준 기능) | ~90% | 🔴 **탈락** |
| **J-2** | **Hero 선택** — 소유물 중 무엇을 중심에 둘까 | 최근 구매 = Hero (룰) | ~75% | 🔴 **탈락** |
| **J-3** | **Angle 결정** — 같은 제품의 어느 면을 볼까 | 제품별 각도 5개 × 세그먼트 10개 = 50개 사전 제작 | ~70% | 🟡 **경계** |
| **🟢 J-4** | **배제와 유예** — 무엇을 빼고, 뺀 것을 언제 다시 꺼낼까 | 드립 순서 사전 설계 | **~55~65%** | 🟢 **생존** |
| **J-5** | 분량·깊이 | 3구간 룰 | ~85% | 🔴 **탈락** |

## 5.2 🟢 Core AI Decision

> ## **AI가 이 고객의 MCM에서 `지금 말할 하나`를 고르고, 나머지를 `다음 호로 미룬다`.**

| 항목 | 내용 |
| --- | --- |
| **Input** | ① 고객이 등록한 소유 제품 ② 제품 속성(디자인·컬러·소재·실루엣) ③ MCM 공식 스타일링 콘텐츠 ④ 시즌 컬렉션 |
| **🔴 Input에서 제외** | **유사 고객 구매 패턴** — §4.2 |
| **Judgment** | **말할 하나 + 미룰 나머지 + 미룬 것의 재등장 조건** |
| **Output** | 한 호. **그리고 미뤄진 것들의 목록(고객에게 보이지 않음)** |
| **🟢 왜 이것이 AI인가** | 미룬 것의 **재등장 조건이 고정되지 않는다** — 고객의 소유물이 늘거나 시즌이 바뀌면 **미뤄 둔 것 중 무엇이 먼저 올라올지가 재계산**된다 |
| **🟢 왜 이것이 재사용 이유인가** | **미룬 것이 다음 호를 낼 이유다.** `18` P-02의 판별 질문 — "두 번째로 쓸 이유가 서비스 안에 있는가" — 에 답한다 |
| **🔴 한계** | **소유 3개 미만이면 미룰 것이 없다.** §2.2 |

## 7.4 권고

**둘 중 하나를 고르는 문제가 아닐 수 있다.**

`45` D-5와 `43` §Customer Journey를 겹쳐 보면 두 방향은 **같은 인프라(고객이 등록·보관하는 소유물 Pass) 위에 선다.**

```
[면세 매장]        여정 × 소유물 → 장면        ← 43의 Core AI, MCM 특수성·무대 보유
      ↓ 구매하면 Pass에 들어간다
[그 이후]          소유물 → 지금 말할 하나 + 미룰 나머지   ← 46의 Core AI, LTV·Engagement 보유
      ↓ 여정이 바뀌면
[다음 면세]        다시 43으로
```

**⚠️ 그러나 이 통합은 이 문서에서 검증하지 않았다(Hypothesis).** AI 판단이 2개가 되므로 `21` E-10(Single Core Capability)과 3주 범위를 다시 계산해야 한다.

**단독 채택이라면: `46`은 현재 상태로 `43`보다 약하다.** 이유는 ① AI 필연성이 고객 소유 개수라는 미확인 변수에 종속되고 ② MCM 특수성이 없고 ③ 검증된 Problem에서 이탈하기 때문이다.
