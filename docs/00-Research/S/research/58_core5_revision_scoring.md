# 2. 🔴 새로 생긴 문제 두 개

## 2.1 Rule Filter가 AI의 발견 공간을 미리 좁힌다

> *"기준1. Core 5 연결 여부 → **5개 축 중 3개 이상 겹치는** 후보"*

**`57`에서 확립한 핵심 원리:** *"Connected enough to feel personal, **different enough to feel like discovery**."*

```
3개 이상 겹침 요구  →  ▶ 덜 겹치는 후보가 AI에 도달하기 전에 잘린다 ◀
                    →  AI가 보는 후보가 `유사도 높은 것`으로 편향된다
                    →  different 쪽이 룰로 제거된다
```

**🔴 그리고 `57` §G에서 데모의 핵심으로 지목한 REJECT 케이스 — "너무 비슷해서 거절" — 는 통과하는데, 반대로 "충분히 다르지만 연결되는" 강한 발견은 미리 잘린다**(Inference·높음).

**🟡 완화:** 3개 겹침이면 2축은 다르므로 그 2축에서 확장이 나올 수 있다. 치명적이진 않다.

## 2.2 Editor / Gatekeeper 분리가 사라졌다

**`57` K-1은 이 설계의 최대 약점이었고, M(딱 하나만 고친다면)이 그 해결책이었다.**

> `57` M: **"Gatekeeper에게 Angle 3개를 익명·순서 섞어 주고 `없으면 없다`를 허용하라."**

**`58`에는 독립 판정 단계가 없다.** `AI Meaning & Selection` → `Editorial Generation`으로, **선택과 생성만 있고 검증이 없다.**

**그리고 더 큰 문제:**

> *"후보가 2개 이상 → AI가 비교 → **가장 의미 있는 후보 1개 선택**"*

🔴 **후보가 여럿일 때 REJECT 경로가 없다.** 반드시 하나가 뽑힌다.

| 후보 수 | REJECT 가능? |
| --- | --- |
| 0개 | 🟡 발행 안 함 — **단 2개월 후엔 Heritage** |
| 1개 | 🟢 "부족하면 발행 안 함" |
| **2개 이상** | 🔴 **불가 — 반드시 1개 선택** |

**Rule Filter가 3축 겹침으로 후보를 만들면 대부분 2개 이상이 남는다**(Inference). **즉 실전에서 REJECT는 거의 나오지 않는다.**
