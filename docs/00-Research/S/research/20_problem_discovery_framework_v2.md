# Problem Discovery Framework v2

> 작성일: 2026-08-04. 1차 자료: 공식 Q&A (`15`). 진단: `16_gap_analysis_after_qa.md`. 원칙: `18_mcm_ai_design_principles.md`.
>
> **v1의 실패 원인:** `근거 공백 중심` 경로로 **공개 문서에서 관찰 가능한 마찰**만 탐색해, 9개 후보 전부가 ① Reactive ② 저빈도 ③ 정보 제공형이 됐다. MCM이 원하는 ① Proactive ② 지속 사용 ③ 구매 전환과 교집합이 거의 없다 [`16` §7].
>
> **v2의 목적:** 다음 Problem Discovery가 같은 실패를 반복하지 않도록 **탐색 규칙과 필터**를 미리 고정한다.
>
> **이 문서는 Problem을 만들지 않는다.** 어떤 Problem을 찾아야 하는지에 대한 Framework만 정의한다.

## Part 1. Standalone MVP Principles

> **Fact 기반:** **"독립개체 standalone로 설계한 후 이후 특정 데이터가 API로 물린다는 것을 전제로 기획을 해보시는 게 바람직할 것 같습니다."** [QA-5-3]

### 1.1 Standalone의 정확한 의미

**Standalone은 "덜 만들어도 된다"가 아니라 "이렇게 만들라"는 아키텍처 지시다**(Inference·높음).

```
[지금]  독립 실행 + 더미 데이터 + 개인 식별 데이터 없음
          ↓ 단, 설계에 표시할 것
[나중]  특정 데이터가 API로 물림
```

**세 조건이 동시에 충족돼야 한다.**

| 조건 | 근거 | 위반 시 |
| --- | --- | --- |
| ① 라이브 시스템 연동 없음 | "기존 이커머스 시스템 QoS에 무리를 주거나 ... 라이브 시스템-데이터 연동을 시도하기는 해커톤 scope상 어렵습니다" [QA-5-3, **Fact**] | 범위 위반 |
| ② 개인 식별 데이터 없음 | "'개인 식별 데이터가 오고 가지 않는다'는 전제 하에" [QA-5-3, **Fact**] · "고객 데이터는 개인 정보 이슈로 제공이 어렵습니다" [QA-5-1, **Fact**] | **통과 조건 위반** |
| ③ 연결 지점이 설계에 표시됨 | "이후 특정 데이터가 API로 물린다는 것을 **전제로 기획**" [QA-5-3, **Fact**] | **v1의 누락 지점** |

### 1.2 4분면 — 무엇을 어디에 둘 것인가

#### ① 지금 구현해야 하는 것 (실제로 작동해야 함)

| 대상 | 근거 |
| --- | --- |
| **핵심 AI 판단 1개** — 문제를 성립시키는 그 하나의 판단·생성·해석·연결 | "아이디어를 보다 뾰족하게 ... 투영" [QA-1-2, Fact] · "AI에 좀 더 무게" [QA-1-3, Fact] |
| **고객이 실제로 겪는 흐름** — 신호 발생 → AI 개입 → 고객 반응까지의 한 경로 | "실제 플로우" [QA-3-4, Fact] · 공식 FAQ "AI는 실제 서비스 흐름 속 사용자 경험과 연결돼 작동" [OFF-013, Fact] |
| **가설과 검증 설계** — 무엇이 참이어야 성립하는지, 어떻게 확인하는지 | "당위성을 찾기 위해 세운 가설과 검증하고자 하는 것" [QA-1-2, Fact] |
| **재사용 이유** — 두 번째로 쓸 이유가 서비스 안에 있음을 보이는 최소 장치 | "지속적 사용 이유" [QA-1-3, Fact] |

#### ② 더미 데이터로 충분한 것

| 대상 | 근거 |
| --- | --- |
| 고객 프로필·구매 이력·행동 로그 | "고객 데이터는 개인 정보 이슈로 제공이 어렵습니다" [QA-5-1, **Fact**] |
| 재고·가격·주문 상태 | "라이브 시스템-데이터 연동 ... 어렵습니다" [QA-5-3, **Fact**] |
| 매장 평면·배치 | "반드시 매장 평면도를 기준으로 하실 필요는 없습니다" [QA-5-2, **Fact**] |
| 면세 가격·파트너 정책 | 비공개 (기존 조사 확인) |
| **명시 규칙** | 더미임을 화면에 표시한다. 공식 FAQ가 "임의 데이터 활용 ... 감점 사유가 될 수 있다" [OFF-004, Fact]고 했으나 Q&A가 "당연히 더미 데이터로 구현해도 무방합니다" [QA-2-3, **Fact**]로 허용했다. **두 진술의 정합적 해석은 "더미 자체는 문제가 아니고, 숨기거나 AI가 흐름과 연결되지 않은 것이 문제"다**(Inference·중간) |

#### ③ 나중에 API가 연결되는 부분 (지금은 인터페이스만 정의)

**v1이 통째로 누락한 영역이다.** 각 Problem은 아래를 **명시**해야 한다.

| 항목 | 기록해야 할 내용 |
| --- | --- |
| **연결 대상** | 어떤 데이터가 물리면 이 서비스가 완성되는가 |
| **연결 시 변화** | 그 데이터가 들어오면 무엇이 달라지는가 |
| **개인정보 경계** | 그 데이터에 개인 식별 정보가 포함되는가, 포함된다면 어떻게 비식별화하는가 |
| **승인 주체** | 누구의 승인이 필요한가 (Q-15·Q-16·Q-20 연계) |

#### ④ 굳이 구현하지 않아도 되는 것

| 대상 | 근거 |
| --- | --- |
| 실물 쇼케이스·하드웨어 | "반드시 실물이어야 할 필요는 없습니다 ... 미니어춰 프로토타이핑 정도도 괜찮고, 실제 플로우와 구현된 형태를 디지털 에셋을 만들어 아이디어 피칭을 하셔도 무방합니다" [QA-3-4, **Fact**] |
| 매장 평면 정확도 | "배치도와 인테리어도 목적에 따라 종종 바뀌기 때문에" [QA-5-2, **Fact**] |
| 계정·로그인·결제 | 개인 식별 데이터 배제 원칙의 귀결 [QA-5-3, Fact + Inference] |
| 모델 자체 개발 | 공식 FAQ "자체 AI 모델 개발은 필수가 아니며 API 활용이 가능" [OFF-014, **Fact**] |
| 다국어 전체 지원 | 검증에 필요한 최소 범위로 충분 (Inference) |
| 확장 운영 구조 | "메타버스 커머스, AI 도슨트는 아직 확대된 서비스로 진행하기에 무리가 있으므로, 가급적 독립개체 standalone으로" [QA-2-3, **Fact**] |

### 1.3 브랜드 자산 사용 (v1 대비 변경) ⭐

| 자산 | v1 처리 | v2 처리 | 근거 |
| --- | --- | --- | --- |
| 브랜드 로고 | 미확인 → 미사용 | **사용 가능** | QA-5-1 [Fact] |
| 제품 이미지 | 미확인 → 자체 촬영·합성 | **사용 가능** | QA-5-1 [Fact] |
| 공식 공개 영상·이미지 (유튜브·인스타그램) | 미확인 | **사용 가능** | QA-2-2 [Fact] |
| **과거 콜라보·연예인 등장 에셋** | — | **⚠️ 개별 확인 필요** | "권리 관계가 끝난 것도 있습니다" [QA-2-2, Fact] |

| 매장 평면 | 미확인 | **필수 아님, 방문 기반 재구성 환영** | QA-5-2 [Fact] |

**전부 "해커톤 프로젝트 목적 하에"라는 범위 제한이 붙는다** [QA-5-1, Fact].

## Part 2. Problem Discovery Framework v2

### 2.1 탐색 순서 (v1과 반대)

**v1:** 공개 문서 → 관찰 가능한 마찰 → Problem
**v2:** Business Goal → 고객 행동 신호 → 그 신호가 끊기는 순간 → Problem

```
[출발]  MCM Business Goal
        Conversion ↑ → 재방문 ↑ → LTV ↑                    [17 문서]
            ↓
[1단계] 고객이 신호를 남기는 순간을 나열한다
        착장 / 장바구니 / 그 밖에 무엇이 있는가?             [QA-4-4, Fact]
            ↓
[2단계] 그 신호 이후 무슨 일이 일어나는지 추적한다
        브랜드가 반응하는가? 고객이 사라지는가?
            ↓
[3단계] 반응하지 못하는 지점을 Problem 후보로 삼는다
            ↓
[4단계] 10개 필터를 통과시킨다
            ↓
[5단계] 제외 패턴에 걸리는지 확인한다
```

**⭐ 1단계가 v2의 핵심이다.** MCM은 두 개의 신호(착장·장바구니)를 예시로 들었을 뿐 [QA-4-4, Fact], 그것이 전부라고 말하지 않았다. **다른 신호를 찾는 것이 이 프레임워크의 첫 작업이다.**

### 2.2 10개 필터

각 Problem 후보는 아래 10개 질문에 답해야 한다. **`아니오`가 하나라도 있으면 후보를 다시 정의한다.**

---

#### F-01. Business Goal과 연결되는가?

| 항목 | 내용 |
| --- | --- |
| **질문** | 이 문제가 해결되면 Conversion 또는 LTV가 움직이는가? |
| **근거** | "구매 전환 conversion을 방해하는 요소를 거둬 내고자" [QA-4-4, Fact] · "재방문 고객들의 LTV를 올리는 데 관심이 많고" [QA-4-1, Fact] |
| **통과 조건** | 둘 중 하나 이상에 **직접** 연결 |
| **실패 신호** | 사업 경로가 "브랜드 이미지 향상"뿐 |
| **v1 실패** | 9개 중 Conversion에 직접 연결된 것이 2개뿐 [`16` §7.2] |

#### F-02. Customer Journey의 어느 순간인가?

| 항목 | 내용 |
| --- | --- |
| **질문** | 발견·탐색·비교·의향 표출·결정·구매·사용·재방문 중 정확히 어느 지점인가? |
| **근거** | "발견부터 구매 전 과정과 구매 후 로열티까지 관통하는" [OFF-019, Fact] |
| **통과 조건** | 한 지점으로 특정되고, **그 지점에서 고객이 무엇을 하고 있는지 한 장면으로 그려짐** |
| **실패 신호** | 여러 단계에 걸쳐 있거나 "여정 전반"이라고 서술됨 |

#### F-03. Customer Engagement를 막는가?

| 항목 | 내용 |
| --- | --- |
| **질문** | 이 문제 때문에 브랜드가 고객에게 더 가까이 가지 못하는가? |
| **근거** | **"Customer Engagement, 즉, 고객과 더 가까이 다가가는 것입니다."** [QA-4-3, Fact] — MCM이 "가장 해결하고 싶은" 문제 |
| **통과 조건** | 문제와 Engagement 결핍 사이에 **인과**가 있음 |
| **실패 신호** | 문제를 풀어도 브랜드-고객 거리가 그대로 |
| **v1 실패** | 9개 평균 3.7/10 — **평가가 아니라 탐색의 실패였다** [`16` R-4] |

#### F-04. LTV와 연결되는가?

| 항목 | 내용 |
| --- | --- |
| **질문** | 이 문제를 풀면 **같은 고객이 다시 올 이유**가 생기는가? |
| **근거** | "기존 재방문 고객들의 LTV" [QA-4-1, Fact] · "지속적인 초개인화 고객관리" [QA-4-3, Fact] |
| **통과 조건** | 재방문·재구매 경로가 설명됨 |
| **실패 신호** | 한 번 해결하면 끝나는 문제 |

#### F-05. Purchase Intent를 막는가?

| 항목 | 내용 |
| --- | --- |
| **질문** | 고객이 **이미 구매 의향을 표출한 뒤** 발생하는 문제인가? |
| **근거** | **"방문 중 제품을 착장해보거나 혹은 이커머스에서 장바구니에 담고 난 이후 구매가 이뤄지지 않을 때 가장 아쉽습니다."** [QA-4-4, Fact] |
| **통과 조건** | 고객이 남긴 **행동 신호**가 특정되고, 그 이후의 이탈을 다룸 |
| **실패 신호** | 관심 없는 고객을 관심 있게 만드는 문제(획득 문제) |
| **비고** | **F-01과 함께 v2에서 가장 중요한 필터다.** MCM이 유일하게 구체적으로 지목한 지점이기 때문 |

#### F-06. AI가 반드시 필요한가?

| 항목 | 내용 |
| --- | --- |
| **질문** | AI를 제거하면 이 경험의 **가치가 사라지는가**? 비AI 기준선은 무엇이고 왜 부족한가? |
| **근거** | "AI에 좀 더 무게를 두고" [QA-1-3, Fact] · "그 기술을 구현하기 위한 **당위성**" [QA-1-2, Fact] |
| **통과 조건** | 비AI 기준선을 **명시**하고, AI가 그 기준선으로는 불가능한 부분을 담당함 |
| **실패 신호** | "AI로 더 편하게" 수준 / 비AI 대안이 더 우수 |
| **v1 실패** | 9개 중 5개가 비AI 대안 우위를 스스로 인정 [`13`] |

#### F-07. Core AI Capability 하나로 설명 가능한가?

| 항목 | 내용 |
| --- | --- |
| **질문** | **하나의** 판단·생성·해석·연결로 압축되는가? |
| **근거** | "아이디어 단순 나열보다 아이디어를 보다 뾰족하게 풀고자 하는 문제/솔루션에 **투영**" [QA-1-2, Fact] |
| **통과 조건** | 한 문장으로 AI가 하는 일이 서술됨 |
| **실패 신호** | 기능이 2개 이상 필요함 |

#### F-08. Standalone MVP가 가능한가?

| 항목 | 내용 |
| --- | --- |
| **질문** | 개인 식별 데이터 없이, 라이브 연동 없이, 더미 데이터로 **핵심 가설을 검증**할 수 있는가? 그리고 **나중에 무엇이 API로 물릴지 표시했는가?** |
| **근거** | QA-5-3 · QA-2-3 · QA-5-1 [Fact] |

| **실패 신호** | 내부 데이터 필수 / **연결 지점 미기재(v1의 공통 누락)** |

#### F-09. 지속적 사용 이유를 만드는가?

| 항목 | 내용 |
| --- | --- |
| **질문** | 고객이 **두 번째로 쓸 이유가 서비스 안에 있는가**? 문제 발생 빈도는 얼마인가? |
| **근거** | "한 번 반짝 one-off 하고, 그 시효가 다하는" [QA-1-3, Fact] · "지속적 사용 이유, 연결성" [QA-1-3, Fact] |
| **통과 조건** | 재사용 이유가 서비스 내부에 있고, 문제가 반복 발생함 |
| **실패 신호** | 재사용 이유가 서비스 밖(신제품·캠페인)에 있음 / 문제가 연 1회 미만 발생 |

## Part 3. 반드시 제외해야 하는 Problem Pattern

| # | 제외 패턴 | 왜 제외하는가 | 근거 |
| --- | --- | --- | --- |
| **X-01** | **Generic Recommendation** — 취향 기반 상품 목록 제시 | 요청이 있어야 작동하고, 브랜드 고유성이 없으며, 재사용 이유가 서비스 밖(신상품)에 있음 | QA-4-3 "한발 앞서" · QA-2-1 "브랜드 세계관" [Fact] |
| **X-02** | **Generic Chatbot** — 질문에 답하는 대화 인터페이스 | 요청 대기형이므로 **말없이 떠나는 고객에게 도달할 수 없다** | QA-4-3 · QA-4-4 [Fact] |
| **X-03** | **One-off Experience** — 한 번 체험하면 끝나는 경험 | "시효가 다한다". LTV에 기여하지 않음 | QA-1-3 [Fact] |
| **X-04** | **AI 없이 가능한 문제** — 정책·프로세스·안내 정비로 해결되는 문제 | AI의 당위성이 성립하지 않음 | QA-1-2 "당위성" · QA-1-3 "AI에 좀 더 무게" [Fact] |
| **X-05** | **기능을 먼저 만드는 접근** — 만들고 싶은 것에서 출발 | "문제/솔루션에 투영"이 아니라 아이디어 나열이 됨 | QA-1-2 [Fact] |
| **X-06** | **단순 운영 효율 문제** — 직원 생산성·비용 절감 중심 | MCM이 지목한 문제는 **고객과의 거리**이지 내부 효율이 아님 | QA-4-3 [Fact] |
| **X-07** | **부분 개선형 문제** — 기존 기능을 조금 편하게 | "단순 부분 변화가 아닌 대전환적" | QA-1-1 [Fact] |
| **X-08** | **기술 시연형 문제** — 기술을 보여 주기 위한 문제 설정 | "고객이 생경하게 여기는 기술 중심 장치는 지양" | QA-3-3 [Fact] |
| **X-09** | **저빈도 예외 처리 문제** — 손상·분쟁·이전 등 드물게 발생하는 상황 | 지속 사용 이유를 구조적으로 만들 수 없음. **v1이 통째로 빠진 함정** | QA-1-3 [Fact] + `16` W-3 |
| **X-10** | **Reactive 정보 제공 문제** — 고객이 알아보려 할 때 정보가 없는 문제 | 요청 이후에만 작동. **v1 후보 9개 전부가 여기 해당** | QA-4-3 [Fact] + `16` W-1·W-2 |
| **X-11** | **매장 내 정밀 측정 문제** — 오프라인에서 수치·치수를 판정 | MCM이 명시적으로 덜 효과적이라고 답함 | QA-3-2 [Fact] |
| **X-12** | **개인 식별 데이터 의존 문제** — 실제 고객 데이터가 있어야 성립 | 통과 조건 위반 | QA-5-1 · QA-5-3 [Fact] |
| **X-13** | **White-label-first 접근** — 범용 서비스를 만들고 MCM을 적용 | 순서가 반대. "덜 생산적"으로 평가됨 | QA-2-1 [Fact] |
| **X-14** | **압박형 전환 문제** — 할인·긴급성으로 구매를 유도 | "높은 가격이 아닌 높은 가치". 전환은 마찰 제거로 | QA-4-2 · QA-4-4 [Fact] + Inference |

**⚠️ X-09와 X-10은 v1이 실제로 빠진 함정이다.** 두 패턴은 **근거를 찾기 쉽다**는 공통점이 있어 `근거 중심` 탐색에서 자연스럽게 선택된다. **근거의 확보 용이성과 문제의 중요도는 상관이 없다**는 것을 기억해야 한다.

## Part 4. 탐색 시작점 (Problem을 만들지 않는 범위에서)

**⚠️ 아래는 Problem이 아니라 `어디를 봐야 하는가`에 대한 지도다.**

### 4.1 MCM이 직접 지목한 신호 (Fact)

| 신호 | 채널 | 근거 |
| --- | --- | --- |
| **착장** | 오프라인 매장 | QA-4-4 [Fact] |
| **장바구니 담기** | 이커머스 | QA-4-4 [Fact] |

### 4.2 아직 나열되지 않은 신호 (탐색 대상)

MCM은 두 개를 **예시로** 들었을 뿐이다. **다른 구매 의향 신호를 찾는 것이 v2 탐색의 첫 작업이다.**

이 작업에서 던져야 할 질문(Problem이 아니라 질문이다):
- 고객이 **말하지 않고 남기는** 다른 행동은 무엇인가?
- 그 행동이 일어나는 **정확한 시점과 장소**는 어디인가?
- 그 이후 고객은 **어떻게 사라지는가**?
- 브랜드는 그 신호를 **읽을 수 있는가, 읽고도 반응하지 않는가**?

### 4.3 조사 공백 우선 해소 (`16` §5)

| 공백 | 왜 먼저 해소해야 하는가 |
| --- | --- |
| **칼리버스** [QA-2-3] | MCM 기존 자산인데 기존 코퍼스에 기록이 없다. 이 위에서 대전환을 만드는 것이 QA-1-1이 말한 "더 빛을 발하는" 조건일 수 있다 |
| **AI 도슨트** [QA-2-3] | 동일. 또한 `05`·`07`의 "MCM 공개 AI는 수요예측 계획뿐" 판정이 부정확할 수 있다 |
| **면세·여행 리테일 구조** [QA-4-1] | 국내 매출의 대부분이며 무대 선택을 좌우한다 |
| **착장·장바구니 이후 이탈의 규모** [QA-4-4] | MCM이 가장 아쉬워하는 지점인데 기존 조사에 항목 자체가 없다 |

## 5. v1 → v2 요약 대조

| 축 | v1 | v2 |
| --- | --- | --- |
| **출발점** | 공개 문서의 관찰 가능한 마찰 | **Business Goal → 고객 행동 신호** |
| **AI 구조** | Reactive (요청 후 응답) | **Proactive (신호 감지 후 선제)** |
| **문제 빈도** | 고려하지 않음 | **필터로 명시 (F-09)** |
| **무대** | 한국 정상 매장 포함 | **글로벌·이동·면세 중심** |
| **브랜드 자산** | 미확인 → 미사용 | **사용 가능 (해커톤 목적)** |
| **Standalone** | "내부 API 불필요"에서 종료 | **연결 지점을 설계에 표시** |
| **Novelty** | 아무도 안 한 것 | **전환의 크기 (기존 위에서도 가능)** |
| **필터 수** | 없음 (품질 검문 10문항) | **13개 필터 + 14개 제외 패턴** |

## 6. 이 문서의 한계

1. **Q&A 원문을 이 조사가 독립 열람하지 않았다.**
2. **필터 우선순위(§2.4)는 이 조사의 설계다.** MCM이 위계를 제시하지 않았다.
3. **더미 데이터에 대한 공식 FAQ와 Q&A의 정합적 해석(§1.2)은 `Inference`다.** 두 진술이 실제로 충돌한다면 이 해석이 틀릴 수 있다.
4. **F-11·F-12·F-13은 v1에 없던 필터다.** 기존 9개 후보를 이 필터로 다시 판정하면 결과가 크게 달라질 수 있으나, **이 문서는 재평가를 수행하지 않았다.**
5. **Problem을 만들지 않았다.** §4는 탐색 지도이지 Problem 목록이 아니다.
6. **칼리버스·AI 도슨트를 확인하지 못했다.** 확인 결과에 따라 §4.3의 우선순위가 바뀔 수 있다.
