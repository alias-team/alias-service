# 1. 경고 1 — "왜 MCM인가"

## 1.1 회복안의 실제 개선

| | 이전 | 회복안 |
| --- | --- | --- |
| 매칭 기준 | **속성** — "검정 가방이라 검정 자켓" | **의미** — "Travel Heritage × Mobility Mood" |
| 필요한 데이터 | 제품 속성 (공개) | **브랜드 시즌 방향성 (내부 지식)** |

**🟢 경쟁 서비스 차별로는 유효하다**(Inference·높음).

| 서비스 | 시즌 방향성 데이터를 갖는가 |
| --- | --- |
| **Stylitics** | 🔴 **아니다.** 카탈로그 속성과 스타일 데이터로 조합을 만든다 |
| **디지털 옷장 앱** | 🔴 아니다 |
| **캡슐 워드로브 AI** | 🔴 아니다 — 카테고리 분포만 본다 |
| **MCM** | 🟢 **갖는다** |

**→ "속성 매칭"에서 "의미 매칭"으로 옮긴 것은 실질적 개선이다.** Stylitics는 시즌 방향성을 모르므로 이 판단을 할 수 없다.

## 1.2 🔴 그러나 로고 치환 테스트는 여전히 실패한다

> **"Prada Re-Nylon Backpack의 Utility Heritage와 이번 FW 시즌의 Function Mood가 연결됩니다."**

**그대로 성립한다.** 모든 럭셔리 브랜드가 헤리티지와 시즌 무드를 갖는다.

**더 나쁜 것은 축 자체가 특수하지 않다는 점이다:**

| MCM의 축 | 다른 브랜드도 갖는가 |
| --- | --- |
| **Travel Heritage** (1976 뮌헨) | 🔴 **Louis Vuitton(1854 트렁크) · Goyard · Rimowa가 더 강하다** |
| 시즌 Mood | 🔴 전부 |
| 아이코닉 패턴 | 🔴 전부 (Monogram · Damier · Nylon) |

**`18` G-02(UVP)의 판별 질문 — "MCM 로고를 떼고 다른 럭셔리 브랜드 로고를 붙여도 그대로 성립하는가?" — 에 여전히 `예`다.**

## 1.3 🔒 MCM만의 축은 어디에 있는가

**이 프로젝트가 확보한 A급 공식 자산 중 다른 브랜드가 못 쓰는 것은 하나다.**

> **"국내 매출도 대부분 면세 매출인 관계로, 실제로 글로벌 고객 기여도는 브랜드 매출의 90% 이상을 상회합니다."** [QA-4-1, **A급 공식**]
> **"글로벌 디지털 노마드이며 연령대는 Gen MZ입니다."** [QA-4-1, **A급 공식**]

**Louis Vuitton은 여행 헤리티지를 갖지만 매출의 90%가 이동 고객에서 나오지 않는다**(Inference·중간~높음).

**→ MCM 특수성은 `여행 헤리티지`가 아니라 `고객이 실제로 이동한다`에 있다.** 이것이 `43`이 면세를 무대로 삼아 확보한 것이고, **Personal Edit에는 이 축이 없다.**

## 🟢 회복됐다. 그리고 이유가 명확하다.

```
[기존 CRM]        신상품 출시 → 누구에게 보낼까 → 발송 → 구매 유도
                   ▲ 출발점이 브랜드 캘린더

[Personal Edit]   내 소유물 → 이번 시즌이 이걸 어떻게 바꾸나 → 새 활용 발견 → 구매
```

**출발점이 바뀐 것이 실질적 차이다**(Inference·높음). 그리고 `48`에서 확인한 것과 이어진다 — **표준 RFM은 오래된 구매를 `lapsed`로 분류해 win-back 대상으로 삼는데** [Fact], **이 서비스는 같은 데이터를 `살아 있는 자산`으로 취급한다.**

| --- | --- |

| **2** | **`21` E-04(Purchase Intent, 9점) 미충족은 그대로다.** MCM이 지목한 것은 **착장 후·장바구니 후** 이탈이다 [QA-4-4] |

# 3. 경고 3 — "왜 AI인가"

## 3.1 🟢 방향은 정확하다

사용자가 제시한 5단계 — **③ 가능한 여러 해석 생성 → ④ 이번 시즌과 가장 적합한 Narrative 선택** — 은 `47` §5.1에서 설계한 **Stage 2(Angle 판단)와 동일하다.** 독립적으로 같은 지점에 도달했다.

## 3.2 🔴 그러나 Kill Test 결과가 바뀌지 않는다

**사용자 예시를 그대로 놓고 본다.**

> Stark Backpack의 해석 후보: **Travel · Street · Heritage · Personalization** (4개)
> 시즌 방향: FW26 = Mobility

**Non-AI 대체:**

| 단계 | 대체 방법 |
| --- | --- |
| 해석 후보 | **제품별 4~5개를 사전 작성** (제품 수백 개 × 5 = 수천 셀, 1회 작업) |
| 시즌 방향 | 시즌당 1~2개 정의 |
| 매칭 | **테이블 룩업** |

> ## 🔴 **해석 후보가 사전 정의되면 4지선다이고, 4지선다는 AI가 아니어도 된다.**

**잔존 ~60~65%. `47`과 동일하며 개선되지 않았다.**

## 3.3 🔒 딜레마 — 그리고 유일한 출구

| 설계 | AI 필연성 | Guardrail |
| --- | --- | --- |
| **해석을 사전 정의한다** | 🔴 **없다 (룰)** | 🟢 안전 |
| **해석을 생성한다** | 🟢 있다 | 🔴 **G-04 위반** — "소재·제작·품질에 대한 근거 없는 생성 설명" 금지 |

### 🟢 출구 — 생성이 아니라 조합

```
해석의 ▶재료◀   =  사실만  (제품 실측 속성 · MCM 공식 시즌 키워드 · 공개 제품 정보)
해석의 ▶조합◀   =  AI 판단  ← 여기에만 AI를 둔다
```

**이렇게 하면 G-04를 위반하지 않으면서 조합 공간을 열 수 있다**(Inference·중간).

**그리고 조합 공간을 실제로 폭발시키는 것은 `해석 후보`가 아니라 `소유 조합`이다:**

```
소유 1개 × 해석 4개 × 시즌 1개 = 4         🔴 룰로 충분
소유 3개 × 해석 4개씩 × 교차 × 시즌 = 수백  🟡 룰이 버겁다
```

**→ AI 필연성은 여전히 소유 개수에 종속된다.** `46`에서 지적한 문제가 회복안으로도 해소되지 않았다.

# 5. 🔴 `48`의 미해결 질문 — 오히려 악화됐다

> **`48`이 남긴 질문: "소유 1개인 첫 고객에게, 옆 사람과 다른 Edit이 나올 이유가 무엇인가?"**

**회복안의 예시 문장을 그대로 본다.**

> **"Stark Backpack의 Travel Heritage와 이번 FW 시즌의 Mobility Mood가 연결됩니다."**

> ## 🔴 **Stark Backpack을 산 사람 전원이 같은 문장을 받는다.**
>
> **이것은 개인화가 아니라 `SKU × 시즌` 매트릭스다.**

**회복안이 판단을 `제품 × 시즌`으로 정의했기 때문에, 같은 제품을 가진 고객이 구분되지 않는다**(Inference·높음). `48`에서 지적한 문제가 **설계에 명시적으로 고정된 셈**이다.

**심사 반박:** *"그럼 Stark Backpack 산 1만 명이 같은 Edit 받는 건가요?"* — **답할 수 없다.**

# 6. 🟢 새 발견 — `빼고 미루는 판단`은 차별점이 아니라 **개인화 장치**였다

**`46`에서 나는 `빼고 미루는 판단`을 "추천과 구분되는 유일한 지점"으로 제시했다. 그것은 절반만 맞았다.**

## 6.1 이력이 갈리면 같은 제품이어도 답이 갈린다

```
고객 A (Stark Backpack 1개)          고객 B (Stark Backpack 1개)
  1호: Travel을 열었다                  1호: Heritage를 열었다
       ↓ Travel은 소진                       ↓ Heritage는 소진
  2호: Street                            2호: Travel
       ↓                                     ↓
  3호: Heritage                          3호: Personalization
```

> ## **같은 제품 하나만 가진 두 사람의 Edit이 2호부터 갈린다.**

**소유물이 아니라 `읽은 이력`이 개인화를 만든다**(Inference·높음).

## 6.2 왜 이것이 §5 문제의 해법인가

| 개인화의 근거 | 소유 1개일 때 | 판정 |
| --- | --- | --- |
| **소유 조합** | 🔴 없음 — 1만 명이 동일 | 실패 |
| **구매 시점** | 🟡 22SS vs 24FW — 차이가 작다 | 약함 |
| **🟢 읽은 이력** | 🟢 **1호의 선택이 2호를 바꾼다** | **성립** |

**→ `46`의 E-2·E-3(미루기, 순서 비고정)은 차별화 규칙이 아니라 `소유 1개 문제`의 유일한 해법이다.**

## 6.3 부수 효과 세 가지

| # | 효과 |
| --- | --- |
| **1** | **재사용 이유가 두 겹이 된다** — 시즌이 바뀌어서(외부) + 지난 호에서 미뤄서(내부). `18` P-02는 **재사용 이유가 서비스 안에 있을 것**을 요구한다 |
| **2** | **AI 필연성이 소유 개수 종속에서 벗어난다** — 이력 축이 조합을 만든다 |
| **3** | **`43`과 논리가 같아진다** — 지난 판단이 다음 판단을 바꾼다는 구조 |

| **AI 필연성의 소유 개수 종속** (§3.3) | 이력 축이 조합을 만든다 |
| **CRM과의 구조적 차이** (`46`) | 추천 엔진은 미루지 않는다 |

**넣지 않으면 §5의 심사 반박에 답할 수 없다.**

---

## 이 문서의 한계

1. **§1.3의 "LV는 매출 90%가 이동 고객이 아니다"는 `Inference`다.** LVMH의 채널별 매출 구성을 확인하지 못했다.
2. **§3.2의 "제품 수백 개"는 추정**이다. **MCM 실제 SKU 수를 모른다.**
3. **§6의 이력 기반 개인화는 `Inference`이며 고객 검증이 없다.** 고객이 "지난 호에서 안 본 것"을 가치로 느끼는지 미검증이다.
4. **Kill Test 잔존율은 이 조사의 판단**이며 실측이 아니다.
5. **MCM charm 라인의 실제 구성을 확인하지 못했다**(Hypothesis).
6. **기존 문서를 수정하지 않았다.**
