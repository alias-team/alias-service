# MCM AI Design Principles & Luxury Guardrails

> 작성일: 2026-08-04. 1차 자료: 공식 Q&A (`15_official_design_intent.md`).
>
> **근거 수준:** `Fact` = MCM 직접 답변. `Inference` = 복수 답변 연결. `Hypothesis` = 미검증 추정.
>
> 이 문서는 **설계 원칙**만 정의한다. Problem·Solution·Feature를 만들지 않는다. `좋은 예 / 나쁜 예`는 원칙을 이해시키기 위한 **패턴 예시**이며 제안이 아니다.

## Part 1. MCM AI Design Principles (12개)

---

### P-01. AI는 요청을 기다리지 않는다 — **Anticipation over Response**

| 항목 | 내용 |
| --- | --- |
| **Principle** | AI는 고객의 질문에 답하는 것이 아니라, 고객이 무엇을 원하는지 **먼저 제시**한다. |
| **근거 (Q&A)** | **"AI를 고객이 원하는 것을 한발 앞서 제시하고"** [QA-4-3] · **"말을 걸어주거나, 경험을 자연스럽게 유도하는 장치"** [QA-3-3] |
| **의미** | MCM이 지목한 이탈 지점(착장 후·장바구니 후)에서 고객은 **아무 말도 하지 않는다** [QA-4-4]. 요청을 입력으로 받는 시스템은 이 순간에 도달할 수 없다. 입력은 **말이 아니라 행동 신호**여야 한다. |
| **좋은 예** | 고객의 행동 신호를 감지해 브랜드가 먼저 반응하는 구조 |
| **나쁜 예** | 고객이 질문·검색·요청해야만 작동하는 구조 |
| **분류** | **Fact** (선제 제시 요구) + **Inference** (행동 신호가 입력이어야 한다는 도출) |

---

### P-02. 한 번이 아니라 계속 — **Continuity over One-off**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 경험은 **다음 사용의 이유를 스스로 만들어야** 한다. |
| **근거 (Q&A)** | **"AR/XR 혹은 다른 미디어 경험도 한 번 반짝 one-off 하고, 그 시효가 다하는 경우가 많이 있습니다."** [QA-1-3] · **"AI와 지속적 사용 이유, 연결성 등을 토대로 설계"** [QA-1-3] · **"지속적인 초개인화 고객관리"** [QA-4-3] |
| **의미** | LTV는 정의상 반복에서 나온다 [QA-4-1]. 재사용 이유가 **서비스 밖**(새 캠페인·신제품 출시)에 있으면 One-off다. 판별 질문은 하나다 — **"두 번째로 쓸 이유가 서비스 안에 있는가?"** |
| **좋은 예** | 사용할수록 축적되어 다음 사용이 더 나아지는 구조 |
| **나쁜 예** | 체험 완료 후 다시 열 이유가 없는 구조 |
| **분류** | **Fact** |

---

### P-03. 기술이 아니라 고객이 앞에 선다 — **Invisible Technology**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 고객이 **기술을 인지하지 못해야** 한다. |
| **근거 (Q&A)** | **"고객이 생경하게 여기는 기술 중심 장치는 지양하고, 좀 더 고객중심으로"** [QA-3-3] · **"경험을 자연스럽게 유도하는 장치이면 무엇이든 좋을 것 같습니다"** [QA-3-3] |
| **의미** | 럭셔리 매장에서 기술이 눈에 띄면 그것은 서비스가 아니라 **장치**가 된다. `무엇이든 좋다`는 표현은 **수단을 묻지 않고 결과만 본다**는 뜻이다 — 자연스러움이 유일한 기준이다. |
| **좋은 예** | 별도 학습·조작 없이 흐름 속에 녹아드는 개입 |
| **나쁜 예** | 고객이 새 기기·새 인터페이스 사용법을 배워야 하는 구조 |
| **분류** | **Fact** |

---

### P-04. 채널마다 AI의 목적이 다르다 — **Channel-Specific Purpose**

| 항목 | 내용 |
| --- | --- |
| **Principle** | **온라인은 정확도, 오프라인은 정서.** 같은 기술이라도 채널에 따라 목적이 바뀐다. |
| **근거 (Q&A)** | **"이커머스 구매 경험에서는 실측 피팅 매칭 등이 구매 실책이나 반품을 낮추는 데 도움이 될 것입니다. 다만, 오프라인 리테일에서 구현할 때는 실측보다는 좀 더 분위기나 인상을 연출하고 긍정적인 이미지를 투영해서 '기분 좋은 쇼핑'을 유발하는 게 더 효과적일 수 있습니다."** [QA-3-2] |
| **의미** | **"정확한 AI가 항상 좋은 AI"라는 가정이 MCM에서는 성립하지 않는다.** 매장은 이미 실물이 있는 공간이므로 측정할 이유가 적고, 온라인은 실물이 없으므로 측정이 반품을 줄인다. |
| **좋은 예** | 온라인에서 사이즈·수납을 정밀 판정 / 매장에서 분위기·인상을 연출 |
| **나쁜 예** | 매장에서 정밀 측정·수치 판정을 전면에 내세우는 구조 |
| **분류** | **Fact** |

### P-05. 브랜드 세계관에서 출발해 범용성을 나중에 추출한다 — **Brand-First, Generalize-Later**

| 항목 | 내용 |
| --- | --- |
| **Principle** | **MCM 고객·세계관에서 시작**하고, 범용적으로 쓸 수 있는 부분은 **그다음에** 판별한다. 역순은 안 된다. |
| **근거 (Q&A)** | **"화이트 레이블 white label 어프로치도 가능하겠지만, 일단 특정 고객, 브랜드의 세계관을 기반으로 최소공약수로 떨어지는 서비스를 구상해보고 범용적으로 쓸 수 있는 부분이 무엇일지 판별해 내는 게 훨씬 더 생산적인 어프로치일 것 같습니다."** [QA-2-1] · **"MCM 주-고객층을 염두에 두고 기획하실 경우 훨씬 더 살아 있는 케이스"** [QA-2-1] |
| **의미** | 화이트 레이블 자체를 금지하지는 않았다. 금지된 것은 **순서**다. 범용 서비스를 만들고 MCM 로고를 붙이는 접근은 "덜 생산적"이라고 명시적으로 평가됐다. |
| **좋은 예** | MCM 고객의 특정 장면에서 출발 → 완성 후 범용 요소를 식별 |
| **나쁜 예** | 범용 서비스를 설계한 뒤 MCM 사례로 예시를 채우는 접근 |
| **분류** | **Fact** |

### P-06. 부분 개선이 아니라 대전환 — **Transformation over Increment**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 기존 프로세스를 조금 편하게 만드는 것이 아니라 **접근 자체를 바꾼다.** 단, 기존 위에 서는 것은 문제가 아니다. |
| **근거 (Q&A)** | **"해 아래 새로운 게 없습니다. 새로운 도전도 기존 프로세스와 솔루션이 있었기 때문에 더 빛을 발하는 것입니다. 도전적인 문제를 던지고, 단순 부분 변화가 아닌 대전환적 솔루션과 도전 과제를 찾는 데 집중합시다."** [QA-1-1] |
| **의미** | **평가 축은 `신규성`이 아니라 `전환의 크기`다.** 기존 자산·프로세스 위에 서는 것은 오히려 "더 빛을 발하는" 조건이다. 반대로 아무도 안 한 것이라도 부분 변화라면 낮게 평가된다. |
| **좋은 예** | 기존 접점을 유지하면서 그 접점의 작동 방식을 근본적으로 바꾸는 것 |
| **나쁜 예** | 기존 기능을 조금 더 빠르게·편하게 만드는 것 |
| **분류** | **Fact** |

### P-07. 가설과 검증을 먼저 말한다 — **Hypothesis over Completeness**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 완성도가 아니라 **무엇이 참이어야 이것이 성립하는지, 무엇을 확인할 것인지**를 명시한다. |
| **근거 (Q&A)** | **"기술 구현의 가능성을 보여주되, 그 기술을 구현하기 위한 당위성을 찾기 위해 세운 가설과 검증하고자 하는 것이 무엇인지 명확히 정하는 것에 무게를 두시기 바랍니다."** [QA-1-2] |
| **의미** | `가능성`과 `무게`가 대비돼 있다 — 기술은 가능성만, 무게는 가설·검증에. **불확실성을 감추는 것이 아니라 명시하는 것이 요구된다.** |
| **좋은 예** | "이 가설이 참이면 성립하고, 우리는 이렇게 확인한다"를 산출물에 포함 |
| **나쁜 예** | 완성된 기능만 보여 주고 전제를 말하지 않는 것 |
| **분류** | **Fact** |

---

### P-08. 하나에 투영한다 — **Sharpness over Breadth**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 아이디어를 나열하지 않고 **하나의 문제에 투영**한다. |
| **근거 (Q&A)** | **"아이디어 단순 나열보다 아이디어를 보다 뾰족하게 풀고자 하는 문제/솔루션에 투영하여 피칭하시는 게 중요합니다."** [QA-1-2] |
| **의미** | 기능이 여러 개면 어느 것도 증명되지 않는다. **투영(project)이라는 단어가 핵심** — 아이디어가 문제 위에 겹쳐져 하나의 상으로 보여야 한다. |
| **좋은 예** | 하나의 판단·생성·해석·연결로 압축되는 구조 |
| **나쁜 예** | 여러 기능을 묶은 플랫폼 제안 |
| **분류** | **Fact** |

---

### P-09. 구매 의향 신호를 놓치지 않는다 — **Read the Signal**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 고객이 **말이 아니라 행동으로 남긴 신호**(착장·장바구니)를 읽고 그 자리에서 반응한다. |
| **근거 (Q&A)** | **"구매 intent 파악입니다. 방문 중 제품을 착장해보거나 혹은 이커머스에서 장바구니에 담고 난 이후 구매가 이뤄지지 않을 때 가장 아쉽습니다."** [QA-4-4] · **"어떠한 형태로든 구매 전환 conversion을 방해하는 요소를 거둬 내고자 합니다."** [QA-4-4] |
| **의미** | MCM이 아쉬워하는 것은 **관심 없는 사람이 안 사는 것이 아니라 관심을 이미 보인 사람을 놓치는 것**이다. 두 신호는 채널이 다를 뿐 같은 의미다 — "이걸 갖고 싶다". |
| **좋은 예** | 의향이 표출된 직후, 이탈 전에 개입하는 구조 |
| **나쁜 예** | 구매 완료 후 또는 문제 발생 후에만 작동하는 구조 |
| **분류** | **Fact** |

### P-10. 전환은 설득이 아니라 마찰 제거로 얻는다 — **Remove Friction, Not Persuade**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 구매를 **압박하지 않고** 구매를 막는 요소를 **치운다**. |
| **근거 (Q&A)** | **"어떠한 형태로든 구매 전환 conversion을 방해하는 요소를 거둬 내고자 합니다."** [QA-4-4] · **"단순히 높은 가격이 아닌 높은 가치를 부여하는 브랜드를 지향합니다."** [QA-4-2] |
| **의미** | 원문이 `방해하는 요소를 거둬 내고자`다 — **제거의 언어이지 설득의 언어가 아니다.** 여기에 `높은 가치` 지향 [QA-4-2]을 결합하면 할인 압박·긴급성 조성·과잉 알림은 배제된다(Inference). |
| **좋은 예** | 결정을 막는 불확실성을 해소해 고객이 스스로 결정하게 함 |
| **나쁜 예** | 할인 카운트다운·재고 임박 알림 등 압박형 전환 유도 |
| **분류** | **Fact** (마찰 제거) + **Inference** (압박형 배제) |

### P-11. 매장에서 시작해 온라인으로 잇는다 — **Offline-Origin, Online-Continuation**

| 항목 | 내용 |
| --- | --- |
| **Principle** | Challenge 02에서는 **오프라인 상호작용을 먼저 진보시키고, 그것을 온라인 경험으로 이어 간다.** |
| **근거 (Q&A)** | **"온-오프라인 연계 경험을 지향합니다. 하지만, 이번 해커톤에서 오프라인 공간에서 더 진보된 상호작용 구현에 무게를 두고 그것을 어떻게 온라인 경험으로 이어 나갈지 살펴 보면 좋을 것 같습니다."** [QA-3-1] |
| **의미** | **방향이 명시됐다.** "온·오프라인 연계"라는 말은 흔히 양방향으로 읽히지만, MCM은 **오프라인 → 온라인** 순서에 무게를 두라고 답했다. |
| **좋은 예** | 매장에서 일어난 상호작용이 온라인에서 이어지는 구조 |
| **나쁜 예** | 온라인 기능을 매장에 설치하는 구조 |
| **분류** | **Fact** |

---

### P-12. 지금은 독립, 나중은 연결 — **Standalone Now, API Later**

| 항목 | 내용 |
| --- | --- |
| **Principle** | 독립 실행 + 더미 데이터 + 개인 식별 데이터 배제로 설계하되, **나중에 어떤 데이터가 API로 물릴지 지금 설계에 표시**한다. |
| **근거 (Q&A)** | **"독립개체 standalone로 설계한 후 이후 특정 데이터가 API로 물린다는 것을 전제로 기획을 해보시는 게 바람직할 것 같습니다."** [QA-5-3] · **"당연히 더미 데이터로 구현해도 무방합니다."** [QA-2-3] · **"'개인 식별 데이터가 오고 가지 않는다'는 전제 하에"** [QA-5-3] |
| **의미** | Standalone은 관대함이 아니라 **아키텍처 지시**다. "내부 API가 필요 없다"에서 멈추면 절반만 답한 것이다. **연결 지점이 설계에 표시돼야 한다.** |
| **좋은 예** | 더미 데이터로 완결 동작 + "이 자리에 어떤 데이터가 들어오면 완성되는가"가 명시됨 |
| **나쁜 예** | 라이브 시스템 연동을 전제하거나, 반대로 연결 미래를 전혀 고려하지 않은 폐쇄 구조 |
| **분류** | **Fact** |

## Part 2. Luxury Guardrails

> MCM이 **훼손하면 안 된다고 직접 지목한 가치**와, 그로부터 도출되는 금지선이다.
>
> **Fact:** **"브랜드 평판, Unique Value Proposition, Silhouette, Craftmanship 등이 있을 것 같습니다. 그리고 단순히 높은 가격이 아닌 높은 가치를 부여하는 브랜드를 지향합니다."** [QA-4-2]

---

### G-01. Brand Reputation — 브랜드 평판

| 항목 | 내용 |
| --- | --- |
| **근거** | "브랜드 평판" [QA-4-2, **Fact**] |
| **금지선** | AI의 오작동·오판정이 **브랜드의 약속으로 오인**되는 구조. 특히 정품 판정·보증 판정·품질 보증처럼 **틀렸을 때 책임이 브랜드로 귀속**되는 출력 |

## Part 3. 원칙 간 우선순위와 충돌 처리

### 3.1 위계

```
[통과 조건]  G-09 Privacy · G-10 System Integrity
             → 충족하지 못하면 시도 불가

[불변 제약]  G-01~G-08, G-11 Luxury Guardrails
             → 위반 시 다른 장점이 상쇄되지 않음

[설계 원칙]  P-01~P-12
             → 이 안에서 설계한다
```

### 3.2 예상되는 충돌과 처리

| 충돌 | 처리 |
| --- | --- |
| **P-01(선제 제시) ↔ G-09(개인정보)** | 개인 식별 없이 선제 제시가 가능한가? **행동 신호는 익명 세션 단위로도 감지 가능**하다(Inference). 개인 식별이 필수인 설계는 통과 조건 위반 |
| **P-09(신호 읽기) ↔ G-05·P-10(압박 금지)** | 신호를 읽고 **개입하되 압박하지 않는** 경계가 필요하다. 판별 기준은 "고객이 스스로 결정했는가" |
| **P-04(오프라인=정서) ↔ P-07(가설·검증)** | 정서적 효과도 검증 대상이어야 한다. "기분이 좋아졌는가"를 어떻게 확인할지 설계에 포함 |
| **P-06(대전환) ↔ P-12(Standalone)** | 대전환적 문제를 다루되 **검증 범위는 좁게** 잡는다. 문제의 크기와 MVP의 크기는 별개다 |
| **P-05(브랜드 우선) ↔ 범용성** | 화이트 레이블 자체는 금지가 아니다. **순서만 지키면 된다** |

## 4. 이 문서의 한계

1. **Q&A 원문을 이 조사가 독립 열람하지 않았다.** 사용자 제공 텍스트에 의존한다.
2. **`좋은 예 / 나쁜 예`는 패턴 예시이며 제안이 아니다.** 특정 기능·서비스를 권하지 않았다.
3. **금지선 대부분이 `Inference`다.** MCM은 가치를 나열했을 뿐 [QA-4-2] 금지선을 명시하지 않았다. 도출은 이 조사의 해석이다.
4. **G-03(Silhouette)의 해석이 불확실하다.** MCM이 이를 제품 형태로 말한 것인지 브랜드 디자인 언어 전반으로 말한 것인지 확인되지 않았다(Hypothesis).
5. **원칙 간 우선순위는 이 조사의 설계다.** MCM이 위계를 제시하지 않았다.
6. **Problem·Solution·Feature를 만들지 않았다.**
