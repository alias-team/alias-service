# 1. CRM 추천 문제 — 🔴 후퇴했다

## 1.1 문제의 문장

> **"당신이 가진 Stark Backpack과 관심을 보인 `Silver Charm`은 이번 시즌 MCM의 Personal Detail 방향과 연결됩니다."**

**`50`에서 제시한 규칙 W-1 — `위시리스트 제품을 Edit에 직접 노출하지 않는다` — 을 어겼다.**

## 1.2 왜 이것이 결정적인가

**포장이 아무리 좋아도, 위시리스트 제품명이 문장에 등장하는 순간 고객은 그것을 결론으로 읽는다**(Inference·높음).

| | 표면 | 고객이 읽는 것 |
| --- | --- | --- |
| **CRM** | "장바구니에 담은 Silver Charm 구매하세요" | **Silver Charm을 사라** |
| **이번 수정** | "…관심을 보인 Silver Charm은 이번 시즌 Personal Detail 방향과 연결됩니다" | **Silver Charm을 사라 (돌려 말함)** |

**심사 반박:** *"결국 장바구니에 담은 거 사라는 거 아닌가요?"* — **답할 근거가 없다.**

## 1.3 🔒 판별선 — Silver Charm이 `목적지`인가 `재료`인가

| | 목적지 (🔴 리타게팅) | 재료 (🟢 해석) |
| --- | --- | --- |
| Edit의 결론 | **Silver Charm** | **Silver Charm이 아닌 다른 것** |
| 위시리스트의 역할 | 팔 물건 | **축을 읽는 단서** |
| 문장 | "…Silver Charm은…" | "당신의 관심에서 `개인 표식`이라는 축이 보입니다. 이번 시즌은 그 축을 이렇게 다룹니다" |

**🔒 규칙: Edit의 결론이 위시리스트 제품이면 리타게팅이다.**

**즉 Silver Charm은 축을 읽는 데만 쓰이고, 지면에는 등장하지 않는 편이 강하다**(Inference·중간~높음).

## 1.4 ⚠️ 그러면 전환은 어떻게 되는가

**이 규칙을 지키면 위시리스트 제품이 안 팔린다.** 이것이 `47` W-7에서 지적한 딜레마의 재등장이다.

| 선택 | 결과 |
| --- | --- |
| 위시리스트 제품을 판다 | 🔴 리타게팅. 차별 소멸 |
| 안 판다 | 🟡 전환 근거 약화. 대신 **"편집이 판매를 지배하지 않는다"는 주장이 성립** |

**결정하지 않고 넘어갈 수 없는 지점이다.**

## 2.1 이 재해석의 세 가지 미덕

| # | 미덕 | 근거 |

| **3** | **Fact / Inference 구분이 설계에 내장됐다** | MCM이 요구한 태도 — **"당위성을 찾기 위해 세운 가설과 검증하고자 하는 것이 무엇인지 명확히"** [QA-1-2, **A급 공식**] |

## 2.2 🔴 그러나 대가가 있다

> ## **해석을 낮추면 AI 필연성도 함께 낮아진다.**

| 진술 수준 | 성격 | AI가 필요한가 |
| --- | --- | --- |
| "이 고객은 Personalization 성향이다" | **추론** | 🟢 판단 |
| "Silver Charm에 관심을 보였다" | **관측** | 🔴 **데이터 조회** |

**`21` E-02(AI Necessity)가 7 → 6으로 내려간다.** 안전해진 만큼 AI가 할 일이 줄었다.

**🔒 이 트레이드오프를 인식하고 설계해야 한다:** 진술은 낮게 유지하되(안전), **판단은 다른 층에 두어야 한다**(§3).

# 3. AI가 실제로 판단해야 하는 것

## 3.1 🔴 제시된 3단계는 전부 룰이다

| Step | 내용 | Non-AI 대체 | 판정 |
| --- | --- | --- | --- |
| **1** | 공통 요소 추출 | 태그 집합 연산 | 🔴 **룰** |
| **2** | 시즌 방향과 연결 | 태그 매칭 | 🔴 **룰** |
| **3** | Edit 생성 | 템플릿 | 🔴 **룰 + 문장 생성** |

**Kill Test 잔존 ~70%. `50`보다 나빠졌다.**

## 3.2 🔴 그리고 Step 1에 논리 오류가 있다

```
Stark Backpack:  Travel · Monogram · Black
Silver Charm:    Personalization · Detail
        ↓
공통 요소:       Personal Expression      ← ❌
```

**이것은 공통 요소가 아니다.** 두 집합에 `Personal Expression`이 없다. **교집합이 아니라 새로 만들어 낸 것이다.**

**→ 이 상태로 심사에 가면 "그건 어디서 나온 건가요?"에 답할 수 없다.** 그리고 근거 없는 생성은 `18` G-04에 걸린다.

### 🟢 논리를 고치는 방법 — `공통 요소`가 아니라 `시즌과의 교집합`

```
소유물 태그 ∪ 관심물 태그
  = { Travel, Monogram, Black, Personalization, Detail }
                    ∩
시즌 방향 태그 (2026 FW)
  = { Personalization, ... }
                    =
              Personalization        ← 이번 호의 축
```

**🟢 이렇게 하면 논리가 맞고, 만들어 내는 것이 없어 G-04에도 안전하다**(Inference·높음).

## 3.3 🟢 그럼 AI는 어디에 필요한가 — 세 자리

| # | 자리 | 왜 AI인가 | 강도 |
| --- | --- | --- | --- |
| **A** | **태그가 사전 정의되지 않을 때** | Stark Backpack의 태그를 사람이 5개 붙이면 룰이다. **제품 이미지·공식 설명에서 추출**하면 AI다 | 🟡 중간 |
| **B** | 🟢 **교집합이 비었을 때** | Black Monogram Backpack × 이번 시즌 `Pastel Softness` → **직접 만나는 축이 없다.** 이때 ① 대비로 연결할지 ② 한 다리 건너 연결할지 ③ **이번 호를 안 낼지**를 판단해야 한다 | 🟢 **가장 강함** |
| **C** | **교집합이 여러 개일 때 + 이미 열었던 축 회피** | `49` §6의 미루기. **이력이 있어야 성립** | 🟢 강함 |

### 🔑 B가 이 검증에서 나온 가장 중요한 발견이다

> ## **교집합이 없는 경우가 오히려 AI가 필요한 경우다.**

**교집합이 있으면 룰로 충분하다. 없을 때 무엇을 할지가 편집자의 판단이다**(Inference·높음).

그리고 **"이번 호를 안 낸다"가 유효한 출력이 되면** `46`에서 찾았던 차별점(추천 엔진은 아무것도 제안하지 않는 출력이 없다)이 자연스럽게 복원된다.

# 5. MCM 차별성을 넣을 자리

## 5.1 현재 왜 없는가

> "이번 시즌 MCM의 **Personal Detail 방향**"

**Prada도 Gucci도 시즌마다 이런 방향을 낸다.** 구조에 브랜드가 없다.

## 5.2 🟢 넣을 수 있는 자리는 하나 — `시즌 방향`의 정의

**이 구조에서 MCM 자산이 들어갈 수 있는 유일한 슬롯은 Step 2의 `시즌 방향` 자리다**(Inference).

| | 일반 브랜드 | **MCM** |
| --- | --- | --- |
| 이번 시즌 = Personalization | "나만의 디테일" | **"이동하는 사람의 표식"** |
| 근거 | — | **매출 90%+가 이동 고객** [QA-4-1, A급 공식] · **"글로벌 디지털 노마드이며 Gen MZ"** [QA-4-1] · 1976 뮌헨 여행 제품 |

### 🔑 이렇게 하면 charm의 의미가 달라진다

```
[일반]  charm = 장식. 예쁘니까.
[MCM]   charm = ▶ 수많은 검은 가방 중 내 것을 알아보게 하는 표식 ◀
                 공항 수하물 벨트에서, 호텔 로비에서, 라운지에서.
```

**🟢 이러면 세 가지가 동시에 붙는다**(Hypothesis, 검증 필요):

| # | 효과 |
| --- | --- |
| **1** | **MCM 특수성** — `이동`은 MCM만 매출 구조로 뒷받침한다 |
| **2** | **charm의 기능적 근거** — 장식이 아니라 이유가 생긴다 |
| **3** | **`43`과 축을 공유** — `Made for Movement`가 두 방향의 공통 언어가 된다 |

**⚠️ 이것은 제안이며 검증되지 않았다.** 그리고 억지스럽게 들릴 위험이 있다 — MCM이 실제로 시즌 방향을 이렇게 규정하는지 확인할 방법이 없다.

## 5.3 그 밖의 후보

| 1976 뮌헨 아카이브 | 🔴 동일 위험 |

# 6. 상품 추천 엔진 vs AI Personal Editorial

## 6.1 축별 대조

| 축 | 추천 엔진 | Editorial |
| --- | --- | --- |
| **최적화 대상** | 클릭·전환 확률 | 🔴 **정의되지 않았다** |
| **성공 정의** | 샀다 | 🔴 **없다** |
| **출력 단위** | **제품** | **축** |
| **아무것도 안 내는 출력** | 🔴 없다 | 🟢 있어야 한다 |
| **시간 개념** | 지금 | 🟢 **다음 호가 있다** |
| **뺀 것의 운명** | 사라진다 | 🟢 미뤄진다 |

## 6.2 🔴 결정적 차이 — 그리고 그것이 약점이기도 하다

> ## **추천 엔진은 성공 지표가 명확하고, Editorial은 없다.**

**심사 반박:** *"그래서 성과는 뭘로 재나요?"*

**"고객이 자기 물건을 다시 보게 됐는가"는 측정하기 어렵다**(Inference·높음). 이것이 Editorial 프레임의 구조적 약점이다.

### 🟢 제안 가능한 대체 지표 (전부 `Hypothesis`)

| 지표 | 측정 대상 |
| --- | --- |
| **다음 호 개봉률** | 재사용 이유가 실제로 작동하는가 |
| **소유물 추가 등록 수** | 관계가 깊어지는가 |
| **두 번째 구매까지의 시간** | LTV 기여 |
| 🔴 **클릭·구매 전환** | **이것을 주지표로 삼으면 추천 엔진이 된다** |

**마지막 행이 중요하다.** 지표를 전환으로 잡는 순간 설계가 추천 엔진으로 끌려간다.

## 6.3 🔒 한 줄 판별

> **추천 엔진은 `무엇을 살까`에 답하고, Editorial은 `내가 가진 것이 지금 무엇인가`에 답한다.**
>
> **위시리스트 제품이 답에 등장하면 전자다.**
